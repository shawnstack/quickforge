工作台 v8 · 塔台 TOWER

DESIGN NOTES · 设计说明

一句话

把 bot 舰队当成一个机场：出港屏回答「接下来谁会醒」，在跑 / 进港回答「谁在干活、谁刚干完」，通告栏回答「哪里卡住了」。不再是一间办公室（v1–v6），也不是一张班表（v7），而是一座信息塔台。

三屏分工

  • 出港 DEPARTURES：bot 心跳与定时任务合并排程，按时间排序，倒计时逐秒走动；最近一班标 NEXT。到点翻牌出局 → 进入「在跑」。
  • 在跑 NOW / 进港 ARRIVALS：执行中的班次带计时与流光；完成落地为进港记录（成功 / 失败 + 一句话结论）。
  • 通告 NOTAM：心跳失败、任务失败、判活跳过。每条带处置动作（催醒 / 进入会话 / 忽略），恢复后自动解除。

数据映射（全部来自现成端点）

界面来源
出港行 / 倒计时GET /api/bots → heartbeat.nextRunAt；GET /api/scheduled-tasks → nextRunAt
周期 / 状态文案heartbeat.intervalMinutes / enabled / lastError + botStatusSummary()
在跑计时busy / status + 前端会话内计时
进港记录任务：/api/scheduled-tasks/runs 真实记录；bot：lastWakeAt 一条 + 打开期间会话内累积
通告heartbeat.lastError / lastIdleReason；任务 runs[].error
抽屉：记忆 / 目标GET /api/bots/:id/memory、/api/agents/:sid/status —— 打开时按需拉取，避免 N+1
动作wake（催醒）、inbox（投喂，30 秒内提前唤醒）、PATCH bots（心跳/间隔/必醒）、ensureBotSessionOpen

诚实边界

  • 出港只展示 nextRunAt 一班，不按间隔外推未来多班——预测越远越假。
  • bot 没有心跳历史端点：进港里 bot 只有「上次唤醒」+ 本次打开期间的累积，不画 24h 热力带。
  • 本稿所有数据为演示种子；「演示流速」仅是设计稿引擎，产品中不存在。

需要拍板

  • 仪器恒暗：出港屏与翻牌钟在深浅主题下都保持深色（像真实信息屏这件「设备」），房间随主题。若评审认为割裂，可让屏幕也吃全局 token。
  • 入口图标 Theater → TowerControl；WorkbenchPortal 签名不变，宿主零改动。
  • 心跳环形记录（服务端可选第二轮）：让进港的 bot 记录从「近似」变「真实」。
