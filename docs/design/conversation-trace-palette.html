对话轨迹 · 配色方案

只改颜色，不改任何结构与交互。主色调收敛到蓝 → 青绿（色相 150–260），不碰靛紫；饱和度按面积分级——小面积给满色，大面积只微带。

一、三个色相

三个色相全部落在蓝绿区间：Input 250（淡蓝）→ Model 228（亮蓝）→ Tools 188（青绿）。饱和度提高得不均匀——小面积元素承担辨识，大面积底色只轻微带色，所以颜色看得见，面板也不会变花。

Input · 用户输入（淡蓝） oklch(0.6 0.1 250)
淡蓝，三条里最弱。用户消息是基准，不该抢焦点。
Model · 模型请求（亮蓝） oklch(0.54 0.18 228)
亮蓝，整个视图的主角。轮次头、选中态、页签都用它。
Tools · 工具执行（青绿） oklch(0.57 0.15 188)
青绿，比 running 的绿冷 30°，类别色与状态色能同时读出来。

三、改前 / 改后对比

改前：只用前景色透明度

Model 28% —— 中灰
Tools 42% —— 深灰

三条轨只有一种颜色，只能靠深浅猜哪条是哪条；失败和普通记录也挤在同一套灰里。

改后：三条轨各有色相

Model —— 亮蓝
Tools —— 青绿

色相负责「这是什么」，明度负责「有多重」，两个维度分开，扫一眼就能定位工具那条。

四、克制的四条硬约束

色相全部锁在 150–260 的蓝绿区间，不碰靛紫（270–300）与品红。这是这套视图的主色调。
彩度chroma 0.10–0.18（Input 最低，Model/Tools 更高）。超过 0.20 才开始像品牌色。
面积分级小面积给满色（条形 70–92%、2px 规则条 78–95%、图标 92%）；大面积只微带（轮次头 10%、选中行 16%、代码块 6%）。这条是「有色彩但不花」的真正机制。
着色面只染数据载体：轨道、条形、徽标、行左侧 2px 规则条。轮次头与选中态保持中性灰——分区和交互反馈不是数据，上色会和「记录类型」抢色相。
语义优先级失败永远是 destructive、运行中永远是 --workflow-done，两者都盖过色相系统。色相只表达「类别」，不表达「状态」。
深色模式同色相提亮但保留彩度（0.81 / 0.15 附近）。第一版把彩度压到 0.07，深色下几乎看不出颜色——那是「灰」不是「克制」。
