ask_user 回显修复 · 视觉与交互方案

聚焦一件事：用户填过的「补充内容」在回执步、历史回显、跳过三条路径上都要稳定回显，并且让「选中的选项」与「补充」在视觉上分成两段语义。本页用静态复刻对比现状与两套方案。

现象 · 用户能感知到的四点

  1. 1
    只填补充、没勾选项时，回执里只剩一行裸文本。和「选中的选项」长得完全一样，没有任何「这是补充」的标记，用户会以为最后写的内容没被带回去。
  2. 2
    补充写在最后一问的自定义框里时，回执行与普通答案同形。选项与补充粘在同一行，扫读时分不清哪部分是我勾的、哪部分是我补的。
  3. 3
    跳过 / 超时后，历史里只剩原始问题清单。服务端 details.answers 为 null，回执布局整块失效，跳过原因和补充信息一起消失。
  4. 4
    回到某一问时看不出「已经填过」。自定义框默认收起、开关文案固定为「补充说明（可选）」；用中文输入法按回车确认候选词，会被当成「下一问」。

方案 A · 答案内两段语义推荐

把每一问的答案拆成「选项 chip 行」+「补充缩进行」，卡片级补充信息固定为独立末行。跳过时同样回显原因与补充。

  • 只有自定义：先给 .quickforge-ask-answer-empty 弱化占位「（未选择选项）」，正文仍是带「补充」标签的缩进行，不再是裸文本。
  • 卡片级补充：固定为末行，1px 分隔线 + .quickforge-ask-review-label 标签；跳过态不再屏蔽。
  • 视觉强度：chip 用 --muted 底 + 细边框；补充行只用 1px 左侧引导线，不加底色、不加阴影。
  • 兼容：.quickforge-ask-review-answer 保留为容器，旧纯文本路径（无结构化答案）不受影响。

方案 B · 合并到最后一问备选

卡片级补充信息不再单独成行，直接挂到最后一问的答案区块下方，整体少一行高度。

助手提问 回执确认
1. 发布前是否跑全套校验？ 跑全套（test / lint / build）
2. 改动范围？ 只改 ask_user 卡片 补充 先只动前端，别碰 dist/ 和 package-dist/。 补充信息 上线前先给我看一张截图。
2 项已确认
  • 优点：少一行；补充与「我最后停在哪一问」在位置上贴合。
  • 缺点：卡片级补充信息不是任何一问的答案，挂在第 2 问下会被读成「第 2 问的补充」，语义冲突。
  • 缺点：跳过时没有任何一问可挂，仍需回到独立行——两套布局并存，反而更难维护。
  • 缺点：两段「补充」标签贴在一起（一问的补充 + 卡片级补充），读者需要靠标签文字区分，扫读成本反而更高。
  • 结论：仅作为对比保留，不推荐落地。

规格与落地

以下 class 全部沿用现有 .quickforge-ask-* 前缀；只有标注「新增」的条目需要新增样式规则。

区块 DOM 结构与 class 说明
回执行（外层） .quickforge-ask-review > .quickforge-ask-review-row > .quickforge-ask-review-content 结构不变，仅内容改成分段渲染
选项段 .quickforge-ask-answer-choice > .quickforge-ask-answer-chip ×N 新增；多选用同一组 chip
补充段 .quickforge-ask-answer-extra > .quickforge-ask-answer-extra-label + .quickforge-ask-answer-extra-text 新增；1px 左侧引导线，无底色无阴影
仅自定义 .quickforge-ask-answer-empty + 上面的补充段 新增；替换裸文本
卡片级补充 .quickforge-ask-remark-block > .quickforge-ask-review-row--remark > .quickforge-ask-review-label 末行 + 1px 分隔线；跳过时保留
跳过原因 .quickforge-ask-review-skip（内联 #i-skip 图标 + 文案） 新增；替代塞进 .quickforge-ask-review-answer 的裸文本
已填写指示 .quickforge-ask-custom-toggle > .quickforge-ask-custom-filled 新增；仅 custom.trim() 非空时渲染
待答补充框 .quickforge-ask-custom / .quickforge-ask-custom-input 保留；初始 hidden 改为按是否有值决定

i18n（src/lib/i18n.ts，en / zh 各一份）

  • 新增 askUserExtraLabel：en Note / zh 补充。
  • 新增 askUserNoChoiceLabel：en (no option selected) / zh （未选择选项）。
  • 新增 askUserFilledHint：en Filled in / zh 已填写。
  • 已有 askUserRemarkLabel（补充信息）、askUserRemarkOptional（可选）、askUserUnanswered（未回答）、askUserSkipReason*，均直接复用。

行为改动

  • buildAskAnswerText 拆段：新增 buildAskAnswerParts() 返回 { choices, custom }；buildAskAnswerText 保留为兼容拼接（测试与纯文本路径仍在用）。
  • 跳过不再屏蔽 remark：askUser-tool-renderer.tsx 去掉 !review.skipped 条件，改为「有 remark 就渲染」。
  • answers = null 分支：askUserReviewRowsFromDetails 允许 answers 为 null 时返回 { skipped: true, answers: [] }（questions 仍要求是数组），从而走到「跳过原因 + 未回答行 + 补充信息」布局，而不是退回原始清单。
  • e.isComposing 守卫：ask-user-card.ts 的自定义框 keydown 里先判 if (e.isComposing || e.keyCode === 229) return，避免中文输入法上屏被当成「下一问」。
  • 回到某问的状态：renderStep 时若 answers[step].custom 非空，则 customBox.hidden = false、toggle 追加 .quickforge-ask-custom-filled，并回填 textarea。

验证口径：tests/frontend/ask-user-card.test.ts 补选择器契约（.quickforge-ask-answer-choice / .quickforge-ask-answer-extra / .quickforge-ask-answer-empty / .quickforge-ask-review-skip）与 isComposing 用例；渲染器补 answers=null 的跳过态断言。之后跑 npm run test / npm run lint / npm run build。
