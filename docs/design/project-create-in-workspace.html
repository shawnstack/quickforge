交互说明

在 workspace 下直接新建项目 · v1

两个入口，一套菜单

  • 空状态：输入框下方的「选择项目」胶囊
  • 侧栏：项目区标题右侧 ＋
  • 两者唤出同一个菜单，仅定位锚点不同

菜单结构（350px）

  1. 搜索框（自动聚焦，按名称/路径过滤）
  2. 项目列表（当前项目右侧打勾，最多 15rem 滚动）
  3. 「选择项目目录…」→ 打开现有的目录浏览弹窗
  4. 「新建项目」→ 就地在菜单内切换为新建面板
两个动作放在列表下方、用 1px 分割线隔开；不再给「选择目录」常驻强调底色，避免和主列表抢注意力。

新建项目面板

  1. 只需填名称，路径不可编辑（固定 ~/.quickforge/workspace）
  2. 路径预览实时跟随输入：workspace/<name>
  3. Enter 提交，Esc 返回列表，再按 Esc 关闭菜单
  4. 创建中：按钮转圈 + 禁用，输入框只读
  5. 成功：菜单关闭、胶囊变为新项目、侧栏插入并高亮

校验规则

  • 空 / 全空格 → 按钮禁用
  • 含 \ / : * ? " < > | → 就地报错
  • 同名文件夹已存在 → 报错并给「直接使用该项目」
  • ⚠️ workspace 根目录本身不接受作为项目

键盘与可达性

  • ↑ ↓ 在列表内移动焦点，Enter 选中
  • 触发器带 aria-haspopup / aria-expanded
  • 错误用 role="status"，不打断输入
  • 所有动效 120–180ms，尊重 reduced-motion

落地需要的后端

  1. 复用 POST /api/filesystem/mkdir（parentPath = defaultWorkspaceRoot）
  2. 再 POST /api/project/path 注册并激活
  3. 或合并为 POST /api/project/create，一次完成、原子性更好
注意：id='default' 的 workspace 伪项目与「同名真实项目」语义重叠；只允许在 workspace 根目录下建子目录即可规避。
