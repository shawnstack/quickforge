run_workflow 工具卡 · 视觉改版提案

现状问题诊断 + 一个主推方向（可交互）+ 两个备选方向。全部尺寸与颜色取自 src/index.css 现有令牌，不引入新色值。

01 · 现状诊断

不展开卡片时，用户 90% 的时间只看到折叠头；而折叠头目前几乎不承载信息。

问题 1

折叠头信息密度过低

只有「工作流已完成 · 4 个智能体 · 12 个工具」一行灰字 + 跑马灯。阶段进度、失败数、总耗时全部不可见，耗时还要 hover 才出现。

问题 2

层级只能靠「缩进 + 变淡 + 缩小」三件事叠加

Agent 行与工具行是同一个构件（图标 + 文字 + 状态），只能靠字号 0.75× 和颜色 78% 区分，读起来像一堆碎行。

问题 3

轨道是断的

每个工具区各自画一条 border-left，Agent 行没有线；阶段之间靠一条渐隐细线分隔。三条不同强度的线混在一起，反而没有「流程」感。

问题 4

状态语义几乎不显色

运行中 / 完成 / 失败在展开体里都是灰的，只有失败有红色。工作流最核心的「跑到哪了、有没有挂」需要靠读文字判断。

现状 折叠头 1 个信息点（标题） + 跑马灯

提案 折叠头 5 个信息点：状态 / 规模 / 阶段进度 / 失败数 / 总耗时

02 · 主推方案：连续轨道 + 状态语义

一条贯穿全部阶段的 1px 轨道；阶段是实心节点，Agent 是轨道上的小圆点，工具调用是挂在 Agent 下方的短刻度。 层级靠「轨道 + 节点 + 状态色」表达，不再靠逐级缩小字号。

03 · 备选方向

如果主推方案的结构改动过大，可以退一步选这两个。

方向 B 阶段胶囊条
工作流已完成 8.4s
侦察 1.2s 设计 1.1s 实现 4.6s 验证 1.3s 收尾 0.2s

条形长度 = 步数占比，颜色 = 阶段状态。优点：一眼看出「哪个阶段最重」；缺点：段宽不可点击、阶段名要另开一行，阶段多时会碎。

方向 C 扁平时序流
工作流已完成 4 个智能体 · 12 个工具 8.4s
定位 workflow 渲染链路 0.9s
搜索文件 "quickforge-workflow-" 0.3s
读取文件 workflow-tool-renderer.tsx 0.2s
对比三套层级方案 1.1s
重写折叠头与轨道结构 4.6s

去掉阶段分组，只保留左侧阶段色条。优点：时序最准、纵向最省空间，适合 8+ 阶段的长工作流；缺点：丢失「阶段」这个心智模型，无法折叠某一段。

04 · 规范与实现映射

全部数值可在 src/index.css 现有令牌内表达，无需新增色值。

尺寸 字号 / 间距 / 轨道
项值说明
折叠头标题 msg × 0.875 = 12.25px 与现有 .quickforge-tool-summary 同基准，weight 500
阶段名 msg × 0.875 与折叠头同级；用颜色（80% fg）而非字号区分主次
Agent 行 msg × 0.875 现状是 0.75×（10.5px）—— 太小，改回与普通工具卡一致
工具行 msg × 0.8125 = 11.375px 比 Agent 行只小一档，不再「跳两级」
序号 / 计数 / 耗时 msg × 0.6875 · mono tab-nums，右对齐，不随内容跳动
轨道线 1px · border 95% 连续贯穿，最后一个阶段不画（无悬空线）
阶段节点 8px 圆 · 1.5px 描边 done 实心绿 / running 实心强调色 + 光环 / error 实心红 / pending 虚线
Agent 点 5px 圆 无描边，直接填充
阶段刻度 10 × 3px · gap 2px · radius 1px 折叠态唯一进度指示；≤ 8 阶段时可用，更多改为「3/8」文字
缩进 阶段 0 / Agent 19px / 工具 32px 三级，比现状少一级（现状 zone 再嵌 list）
颜色 状态语义（仅新增 done 一处派生）
状态色值出现位置
done--done · oklch(0.55 0.13 158)刻度、阶段节点、Agent 点
running--accent-fg · 蓝 / 深色琥珀刻度脉冲、节点光环、流光文字
error--destructive刻度、节点、Agent 点、工具名、错误块
pending--border刻度、节点（虚线）

说明：现状注释里已声明「完成 = emerald」，但 CSS 里没有落地。本方案补上 --done， 浅色 oklch(0.55 0.13 158) / 深色 oklch(0.75 0.15 160)，与 --destructive 同明度档位。

风险 实现前需要确认的三件事
项说明
测试断言 tests/frontend/workflow-renderer.test.ts 有 3 处对 CSS 源码做正则断言（359/367/378 行），改 CSS 必然失败，需同步更新
阶段刻度上限 阶段数 > 8 时 5px 刻度会溢出折叠头；建议 > 8 时退化为 3/8 文本
跑马灯位置 折叠头主行已经承载 5 个信息点，跑马灯若仍塞在主行会挤掉耗时；建议运行时用它替换 meta 位
