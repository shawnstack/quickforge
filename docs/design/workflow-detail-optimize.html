01 · 现状复刻与问题诊断

左侧按当前生产实现 1:1 复刻（静态、运行中形态）。单页合并的结构是对的，问题集中在「读数效率」：概览条混入配置回显、网格噪声、运行中没有「现在」的参照、阶段在时间轴上没有跨度、失败定位靠肉眼扫。

  1. P1
    概览条第二行信息过密，且混入配置回显。「并发峰值 · 节省 · 预算 24 agent / 64 tool」一行挤四件事；预算是脚本的配置不是运行事实，却和派生统计同权重常驻。
  2. P2
    网格线逐行重复。每行画 5 条刻度线，N 行就是 5N 条竖纹；刻度条已经吸顶常驻，行内网格是冗余噪声。
  3. P3
    运行中看不到「现在跑到哪」。时间轴是纯历史记录，没有当前时刻游标；只能靠状态 pill 的呼吸点猜进度。
  4. P4
    阶段在时间轴上没有跨度。阶段头只有文字 + 时长，看不出阶段之间是串行还是交叠——而这恰是 parallel / pipeline 的核心语义。
  5. P5
    并行组边界弱。只有虚线描边 + 组首一个「并行」，组有几条、从哪到哪，都要靠对齐条形自己数。
  6. P6
    失败定位靠滚动扫视。错误横幅只报文字，与失败步骤行之间没有联动；几十个阶段的长跑里找红行很费眼。
  7. P7
    日志没有容器感。与步骤行同底色混排，扫读时容易被当成步骤；长日志无限拉长阶段。
  8. P8
    展开体打断时间轴阅读。插在行之间的展开内容没有视觉锚点，属于哪一行只能靠缩进猜；网格线还会穿过文字。

02 · 优化决策

每条对应一个 P 编号；全部是渲染层改动，时间轴几何（标签列 / 安全区 / 百分比条形）与单页合并结构保持不变。

#现状优化后
P1第二行塞派生统计 + 预算 + 图例概览条减负：第一行 状态 + 耗时 + 规模 + 图例；第二行只留派生统计（并发峰值 / 节省，无则整行隐藏）。预算迁入「脚本」sheet 头部——它属于脚本配置，和脚本放一起。
P2每行 5 条网格线共享网格层：阶段区垫一层 z-index:-1 的竖线（25/50/75），只在没有实底的地方露出；行内不再画。展开体 / 日志块有实底自动遮线。
P3运行中无当前时刻参照运行游标（playhead）：轴绘图区挂耗时 chip，阶段区挂同百分比竖线，贯穿所有行。终态自动消失。
P4阶段头无时间表达阶段跨度条：阶段头轨道画该阶段 min-start → max-end 的细条（与行绘图区同一几何），阶段串/并行结构一眼可读；阶段耗时右移到耗时数字列，与行耗时对齐。
P5虚线 + 组首「并行」并行组 bracket：组左缘一条 2px 竖轨 + 组首一次「并行×N」；虚线描边保留（双编码不删）。
P6错误横幅只有文字定位失败步骤：横幅右侧按钮滚动到失败行并闪烁描边 1.6s（reduce-motion 降级为纯滚动）。
P7日志与步骤同底色混排console 块 + 折叠：日志收进描边容器（实底遮网格线）；超过 6 行折叠为「展开全部 N 条」。
P8展开体无归属锚点左 rail + 实底：展开体左缘 2px 竖线连到行首图标下方，背景实底遮住网格线，视觉上明确「挂在所属行」。

03 · 优化原型（可交互）

试试：切「运行中」看轴上的现在 4m10s 游标与推进中的条形；切「失败」用横幅里的「定位失败步骤」跳到红行；点阶段头折叠、点任意行展开；切 380 宽度看窄面板退让；深色 / 减少动效随时切。底部「脚本」sheet 头部是预算的新家。
