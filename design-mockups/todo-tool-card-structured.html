todo_write 工具卡 · 结构化展开设计稿

修复：聊天内「更新任务清单」工具卡展开后只有 JSON、没有结构化任务列表；compact 模式展开为空。展开体补结构化列表，视觉模式与置顶摘要任务小节 / 聊天内 todo 胶囊同源。

设计决策

  1. 行结构复用置顶摘要任务小节（GitToolsPinnedSummary.tsx:802-809）：每行 = 状态图标 + 任务文本（+ sr-only 状态文案）；图标 14px 与工具卡 type-icon / 状态图标同尺寸体系。
  2. 字号按工具卡基准收紧：置顶摘要行是 text-sm（面板语境），工具卡展开体取 text-xs（0.75rem / 行高 1.4 / 行高 26px 对齐摘要行 rhythm），更符合 DESIGN_LANGUAGE「紧凑一致、辅助信息弱化」。
  3. 三状态规则：pending = 空心圆（muted-foreground）；in_progress = 半填充圆 + accent（color-mix(in oklab, var(--primary) 78%, var(--foreground))，与聊天内胶囊 quickforge-todo-summary-item--in_progress 同配方）+ 正常字重；completed = 实心勾 + emerald rgb(4 143 101)（置顶摘要与胶囊共用的完成语义色）+ 文字 text-muted-foreground 弱化 + 1px 删除线。
  4. in_progress 备选（见状态图例）：spinner（运行语境、与工具状态图标 animate-spin 同源）；amber 时钟（置顶摘要面板内现案 Clock3 text-amber-600）。主案选「半填充圆 + accent」：静态不转、无色彩噪点，且与聊天内胶囊同为聊天流内的 todo 展示，视觉模式统一。
  5. compact / detailed 差异：compact 展开 = 仅结构化列表（修复展开为空）；detailed 展开 = 列表在上 + 保留现状 Input / Details JSON 块在下（结构不变，仅前插列表）。
  6. 进度条不采用：进度已在摘要行「更新任务清单 · 3/5 已完成」中；进度环是输入框上方胶囊的形态锚点（独立组件语义），复制进工具卡会引入新视觉模式（DESIGN_LANGUAGE「不引入新视觉模式」）。
  7. 类名避让：实现落点新增类沿用渲染器既有 quickforge-todo-history-* 前缀（如 quickforge-todo-history-list / -item），不复用胶囊摘要的 quickforge-todo-summary-*（tests/frontend/todo-write-renderer.test.ts:61 明确禁止渲染器包含 quickforge-todo-summary-list）。
  8. hover 行态：仅加轻背景 color-mix(in oklab, var(--muted) 55%, transparent)（工具摘要行 / subagent 摘要按钮同配方），无位移、无逐行边框阴影；列表超 5 项时 max-height: 7.5rem 内滚动（对齐胶囊规则）。深浅色本稿只做默认浅色，token 全部走语义变量。
