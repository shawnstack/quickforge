edit / write 工具 Diff 显示优化 · 设计稿

同一数据源（details.diff.text 的 unified diff）三种形态对比。页面 JS 即「解析 unified 文本 → 行号 → 配对删/加行 → token 级对比」的实现原型，落地时同构移植。

  • 现状痛点（对照第一张卡）：① +/- 前缀字符与整行底色语义重复，白占一列；② 无行号，无法定位改动位置；③ ---/+++ 文件头两行冗余（路径摘要行已有）；④ @@ hunk 头机器向，多 hunk 间行号跳变无省略提示；⑤ 行级着色下，一行只改几个字符看不出改了什么（edit 场景最常见）；⑥ 增/删文字色为固定深绿/深红，暗色主题下对比度不足（切到暗色看第一张卡）。

方案说明

形态内容解决
方案 A剥离 +/- 前缀；old/new 双行号列（删行只占 old、加行只占 new，sticky 固定于横向滚动）；文件头两行合并为标题行 path（新文件带标记）；@@ 头替换为「⋯ 省略 N 行」分隔（由 hunk 头行号差计算）；语义色 token 化并补暗色文字色。①②③④⑥
方案 B（推荐）在 A 基础上对配对的删/加行做 token 级对比（单词 + 空白 + 符号三分段 LCS），真正变化的字符段用加重底色标出；未配对的新增/删除行保持整行底色。⑤（①–⑥ 全解）

实现落点（若定稿）

  • src/lib/local-tools.ts：renderDiff 由逐行分色改为结构化解析（本稿 parseUnified / annotatePairs / lcsMark 纯函数可直接移植并单测）；diffLineStyle 内联样式双保险同步收敛。
  • src/index.css：diff 行样式 token 化（--add-fg 等），补 html.dark 文字色；新增行号列 / gap 分隔样式。
  • i18n：新增「省略 N 行」「新文件」两键（en/zh）。服务端与协议零改动（text-diff.mjs 输出不变，全部为前端解析）。
  • 不在本范围：摘要行里程计（已上线不变）；审批卡 buildInlineDiff 是独立路径；上下文行折叠（服务端仅给 3 行上下文，无可折叠内容）。
