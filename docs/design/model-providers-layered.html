分层结构

每层只回答一个问题：去哪找、改什么、怎么保存
L1 提供商列表扫状态、模型数与地址，点行进入
L2 提供商详情连接摘要 + 模型目录，高频操作就地完成
L3 单项抽屉连接 / 模型 / 发现 / 请求头，各自保存
L4 高级折叠低频配置与删除，默认收起
01 · L1

列表只负责找和选

每行固定展示连接状态、模型数、Base URL 与模型摘要；连接异常在详情页用明确的重试承接。搜索覆盖提供商、地址和模型 ID。

02 · L2

一屏完成高频操作

连接摘要留在页头，编辑连接不占首屏；模型列表成为主体，可见性开关就地生效。这里的开关直接对应模型选择器里的 quickforgeHidden 语义。

03 · L3

抽屉一次只处理一个对象

编辑连接、编辑模型、发现模型、请求头互不覆盖，各自保存。连接改动会回到“未测试”，模型改动只刷新列表中的一行。

04 · 新建

新建不再复用编辑表单

模板只出现在“添加提供商”的连接层。创建后直接落到空模型状态，顺势引导“发现模型 / 手动添加”，不再要求一次理解全部配置。

05 · 密钥

密钥不再回填明文

连接抽屉显示“已保存 + 替换 / 移除”，留空不会覆盖。provider-keys 现按名称存储，建议同期改为按 provider.id 存储，去掉改名双写与迁移分支。

06 · 能力

测试与发现拆成两个动作

提供商级测试不再依赖“先有一个模型”；模型抽屉里仍可测试单个模型。“发现模型”读取 /v1/models 后勾选导入，需要新增服务端代理。

范围与取舍

本稿只定义信息架构与交互，不含代码实现。「发现模型」和「提供商级测试」需要新增服务端接口；模型运行时、目录解析与现有存储读取语义保持不变。示例数据仅用于版式预览。
