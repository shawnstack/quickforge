# 独立 bot：一个会话、一张嘴、一双自己会动的手

> 状态：**已落地**。实现细节、数据形状与接口见 [server/bots](../../wiki/server/bots.md)；本文只留设计判据和不做什么。
> 前置：[自进化回路](./self-evolution-loop.zh-CN.md)、[一个主体两只手](./cross-project-orchestrator.zh-CN.md)、[设计语言](../../DESIGN_LANGUAGE.md)。

## 1. 一句话

**一个 bot = 一个持久会话。** 对话和它自己干的事发生在同一个上下文里，所以永远不需要「切换视图」。

这一条决定后面所有的取舍：

- 因为只有一个上下文，状态就不能靠另开一块看板表达，只能靠常驻的小信号（侧栏那一行字、输入框上那只吉祥物）。
- 因为会话永不重置，上下文卫生得靠它自己管：读油表、自己触发压缩、把结论写回 `MEMORY.md`。服务端不替它裁剪，也不替它算账。

## 2. 它的家

bot 有独占目录 `<dataDir>/bots/bot-<id 前 8 位>/`，并注册成 `kind: 'bot'` 的项目——文件工具能写哪儿、系统提示词里的 `<workspace_context>` 说什么，都靠这个项目身份，不用另开通道。

目录名由 id 决定，不用显示名：名字可以随时改、可以是中文和空格，路径不受影响。

**它不是「用户的当前项目」。** 打开一次 bot 不该让之后每次「新对话」都落进 bot 目录，所以「当前项目」的每一个写入口都拒绝 bot 项目。

## 3. 心跳：有信号才醒，醒了才算一行

每 30 秒扫一遍，只有到点**且有信号**的才叫醒模型。信号全是文件事实（新文件、`.bot/inbox.md` 有内容、从没醒过），判定不花 token。

- **不醒的那一班不往对话里写任何东西**，只把下次时间推后。这是「心跳」和「打卡」的分界：一小时一次，如果每班都往流里写「我醒了」，一天就把会话淹了。
- **醒来的那一班写一行**，并且写明白这是它自己醒的，不是你说了什么。心跳走的是普通 prompt 通道，落库后 role 就是 `user`——不带标记，界面上就是一串用户从没打过的字。标记落在消息自己的 `details.quickforgeBotHeartbeat` 上（正文 `[心跳]` 前缀只作为旧数据的兜底），渲染成细窄的一行，指令原文默认收起。
- **你正在跟它说话时，这一班直接跳过**：不排队、不抢上下文。

## 4. 撞车规则

| 情形 | 行为 |
| --- | --- |
| 你说话时它正在干活 | 消息排队，不打断当前动作；它干完这一步就回你，并说明刚才在做什么 |
| 它醒来时你正在跟它聊 | 跳过这一班，记一笔 idle |
| 你让它停 | 立刻 abort；已改的文件留在原地，不自动回滚 |

## 5. 状态只在这三处表达

1. **侧栏那一行字**（`botStatusSummary`）：出错 > 在忙 > 睡了 > 上次醒来多久前 > 还没醒过。侧栏行首那只吉祥物只有 24px（球径 14px），眼睛的动作演不出来，所以状态靠文字讲。
2. **吉祥物本身**：侧栏行首 24px、输入框右上角 79px（球径约 46.3px —— 尺寸给小的直接后果是「压扁拉伸只有 3px，看着像没动」；给到 104 又会压住消息区，被否「太大了」；84 之后用户两次要求再小，79 已贴着 46px 球径下限，再小需要用户拍板下调下限），动作由 `resolveMascotState()` 从现有信号推导（出错/等审批 → alert，工具执行 → working，流式 → thinking，刚完成 → happy，心跳关 → sleepy，其余 idle）。
3. **设置弹窗**：吉祥物外观、工作空间路径、`MEMORY.md`、心跳开关与间隔。

刻意不做顶部常驻存在条、右侧手边栏、仪表盘和「手上几单」这类计数。它们要求系统替 bot 维护一份「它在干什么」的账本，而那份账本一定比会话本身晚、也一定会漂；心跳有信号才醒之后，**会话流本身就是最准的账本**。

## 6. 视觉约束（照 DESIGN_LANGUAGE）

| 约束 | 落法 |
| --- | --- |
| 状态用 `data-tone` 驱动，不在 className 拼颜色 | 照 `WorkflowRunDetailContent.tsx:243` |
| **不要用 `animate-pulse`**（已被等待气泡占为 DOM 契约） | 呼吸点自写 keyframes + `prefers-reduced-motion` 降级 |
| 动效引用 token | `--quickforge-dur-*` / `--quickforge-ease-out` |
| 「它自己醒的」那一行靠边框和缩进区分，不靠色块 | 左边框一条，不填底色 |
| 折叠只改高度不改列宽 | 展开正文不与流抢宽度 |
| 空状态不卡片化 | 首开用一行弱化文字 |
| 危险色克制 | 只有「卡住」用红，且必须配文字 |
| 不用未白名单的语义色透明度 | 照 `semantic-color-class-parity.test.ts` |

样式落点：组件自持 CSS（像 `goal-inspector.css` / `conversation-trace.css`），不改 `src/styles/index.css`。

## 7. 不做

- 不做仪表盘、不做统计图表。
- 不拆成「对话」和「工作台」两个视图。
- 不显示置信度 / 心情 / 思考中装饰。
- 状态不用 toast——它不能自己消失。
- 不让自主班次长成消息气泡。
- 不合并「定时任务」页：那里放的是**你排的日程**，这里是 **bot 自己的节拍**。
- 不给 bot 记录加 `skills` 字段：技能归属全局与项目，per-bot 开关从来没传给会话，已删。
- 不做「连续静默 N 班」这类需要长期基线的指标；没有基线就只是噪声。
- 不允许 fork 或回滚它的对话（`BOT_CHAT_CAPABILITIES` 关掉 `forkFromMessage` / `rollback` / `retry`，服务端 `rollbackSessionMessages` 对 bot 项目无条件 403 `BOT_SESSION_IMMUTABLE`）。会话是它的**记忆**，不是可编辑的工作区：fork 会复制出一份带着同样记忆和心跳指令的分身；截断会让记忆和压缩指针脱钩——压缩后的摘要本身就是数组里的一条消息，回滚到压缩点之前指针悬空、回滚到之后摘要描述的那段已不存在，之后每轮喂给模型的都是幻象。轮次写错了就接着说，不剪历史。文件回滚（只恢复被改坏的文件、不碰 messages）不在此列，照常可用。

## 8. 还没解决

1. **永久会话的退化怎么发现。** 压缩会丢细节，且退化是渐进的；「压完之后它变笨了吗」目前没有判定手段。
2. **「它想去哪」缺数据源。** 界面能显示它做过什么，显示不了它长期想成为什么——这需要它自己维护一份意图列表，现在没有。
3. **多 bot。** 本文假设只有一个；多个时侧栏的形态要重想。
