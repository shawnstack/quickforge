模型与提供商：从「一个表单管全部」到「提供商 → 连接 → 模型」三层

现状是新增/编辑共用一整页表单：预设、名称、地址、密钥、协议、请求头和全部模型挤在一起，一次保存写回所有内容—— 改一个模型的上下文窗口也要打开整页表单，协议藏在「高级」折叠里，测试连接必须先填好一个模型。 这一版把它拆成三层：提供商列表（入口与状态）→ 连接配置（独立保存）→ 模型行（独立编辑），每层各自保存、互不牵连。

01

三层解耦，各自保存

连接配置（L2）与模型（L3）分离：换密钥、改地址不触碰模型；每个模型行独立编辑、独立保存，改一个模型不再打开整页表单，列表与滚动位置始终保留。

02

主从布局，窄屏抽屉

左列表右详情，与技能页提案同一模式；窄屏下详情变成抽屉，返回只有一步。深链（从自定义模型入口跳转到指定提供商）改为直接选中列表项。

03

密钥独立成层

密钥状态常显（已配置 / 未配置），「更换 / 添加」展开行内编辑，保存只写 provider-keys 存储；不再把明文密钥回填进大表单来回传递。

04

预设移入「添加」入口

表单里那排预设 chips 移除；「添加」弹出预设选择，选中即生成提供商草稿并进入连接层补全。添加自动发现类服务器（Ollama / LM Studio / vLLM）成为一等入口。

05

测试与发现分层

提供商级「测试连接」不再依赖先填模型（建议新增 POST /api/providers/test）；模型行内「测试此模型」复用现有 /api/models/test-connection；「从服务器拉取模型」建议新增 GET /api/providers/discover。

06

协议升级，可见性下沉

协议从「高级」折叠提升为连接层基本信息（分段选择）；「在选择器中显示」开关直接放在模型行内，不展开即可切换；「高级」折叠只保留自定义请求头。

实现切分（对齐后执行）

存储结构不变，前端拆组件，服务端补两个接口
  • 组件拆分：CustomProvidersSettingsTab → ProviderListPane / ProviderDetailPane / ConnectionSection / ModelListSection / ModelRow；settings-tabs.ts 挂载与 customProvider 深链保持兼容。
  • 存储不变：custom-providers-store 与 provider-keys-store 结构照旧；模型行保存 = 读取该提供商 → 改单模型 → 写回；密钥仍按提供商名单独存储。
  • 建议新增服务端接口：提供商级测试（不带模型）与服务器模型发现；模型级测试复用现有 /api/models/test-connection。自动发现类型使用 CustomProviderType 已有的 ollama / llama.cpp / vllm / lmstudio。
  • Tab 更名：customModels → 「模型与提供商」，搜索关键词增补 provider / 提供商 / 网关。
  • i18n：新增文案 zh / en 成对补齐；设计规范：全部复用 settings 现有控件与 token，不引入新视觉模式（DESIGN_LANGUAGE.md）。
