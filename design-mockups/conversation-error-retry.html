对话报错重试 · 交互定稿（方案 A 简化版）

调研范围：回合失败的终态错误——服务端合成 stopReason='error' 的 assistant 消息，pi-web-ui 渲染红色错误块 （Messages.js：bg-destructive/10 text-destructive rounded-lg + <strong>Error:</strong>）， QuickForge 展示层 decorateAssistantErrorText 把 8 类已知错误串翻译为本地化文案。这是与 SSE 重连提示（reconnect-notice）、 模型流自动重试提示（model-retry-notice）并列的第三层：前两层管「正在自动恢复」，本层管「恢复失败后的用户决策」。 用户已选定方案 A 并要求更简洁——定稿为一行式：⚠ + 一句错误 + 重试按钮 +「详情」就地展开技术原文，多次失败才多出一行琥珀提示。

1 · 现状复刻（对照基准）

按真实 DOM 镜像：错误红块下方挂常显弱化操作行（icon-only「继续生成」▶）；真正的「重试」入口在最后一条用户消息的 hover 操作行里（icon-only ↻，触发 retryFromMessage 裁剪重生成）。把鼠标悬停在用户消息上可见。

  • 恢复入口分裂且动词不明。错误旁边只有一个 icon-only ▶「继续生成」（hover 才有 title）；名字叫「继续」、动作可能是重发原消息（发送失败 stash）也可能是发一条「继续」消息（onContinueAfterError 两条分支）。而真正语义上的「重试」（裁剪重生成）却在上方用户消息的 hover 行里——触屏无 hover，桌面用户也要回头找。
  • 红块重、中英混排。<strong>Error:</strong> 前缀恒英文（pi-web-ui 无本地化），后面接译文或原始英文技术串；大面积 bg-destructive/10 红块与全应用的轻量行词汇（已停止 / 重新连接中 / 模型重试中）反差强烈。
  • 无错误分类与建议。网络失败、超时、配额、上下文超限一律同款红块；8 条已知规则只翻译了文字，没有告诉用户「下一步该做什么」。
  • 重试无过程反馈。点重试后错误块被裁剪、回合重新生成，中间没有「正在重试」过渡——与另外两层提示的存在感不成比例。
  • 反复失败无升级。弱网下同一错误反复出现，界面永远停在第一次失败的形态，没有「多次失败 → 检查网络 / 换模型」的引导。

2 · 定稿：一行式错误行

错误呈现压缩为一行（对齐「已停止 / 重新连接中 / 模型重试中」的轻量行家族）：⚠（唯一的红）+ 一句错误译文或原文 + 常显 「重试」「详情」两个小按钮。默认只有这一行；点「详情」就地展开技术原文（数据层的英文原串，mono 小字折叠块）—— 已知规则命中译文时行内显示译文、原文收进详情；未匹配的错误行内即原文，不显示详情按钮。连续失败 ≥2 次才追加一行琥珀提示。

  • 一行式：⚠ +「生成失败 · 原因」+「重试」「详情」。红色只出现在图标与这一行文字上，视觉权重与「已停止 / 重新连接中」完全同级；未匹配的错误行内直接显示原始串（此时无详情按钮）。
  • 详情就地展开：行内的译文是给人看的，点「详情」展开 mono 小字的英文原串（数据层原文，报 bug / 对照日志用）；仅译文命中（≠原文）时显示该按钮。展开区只读，无复制等附加动作。
  • 就地重试、动词统一：「重试」按钮常显在错误旁边（不依赖 hover）；行为统一——发送失败重发原消息，否则裁剪重生成（等价 retryFromMessage）。上方用户消息 hover 行的 ↻ 保留，作为历史习惯入口。
  • 重试中状态行：点击后错误行原地替换为「⟳ 正在重试…」（复用 model-retry-notice 的 spinner 行词汇）；成功后淡出、助手内容流入。
  • 升级提示（连续失败 ≥2）：仅此时追加一行琥珀「已重试 n 次仍失败 · 可能是网络或当前模型不稳定 · 切换模型」——把用户从无效循环里捞出来，平时不占任何空间。

4 · 实现改动清单

  1. 展示层把终态错误红块改写为一行式错误行：decorateAssistantErrorText 同一位置扩展——替换 div.bg-destructive\/10 的呈现为轻量行（数据层 errorMessage 原文不动），先例是 decorateAssistantStoppedText 对 aborted 标签的样式改写。
  2. 「详情」就地展开技术原文：点击行内「详情」切换折叠块（mono 小字显示 errorMessage 原始英文串）；仅 translateErrorMessage 命中（译文≠原文）时渲染详情按钮，未匹配错误行内已是原文。重试/状态切换时自动收起。
  3. 「重试」按钮统一语义：有 retryFailedPrompt stash → 重发原消息；否则走 retryFromMessage（最后用户消息裁剪重生成）。现状 onContinueAfterError 的两条分支收敛到这里；「继续生成」icon 按钮与其操作行移除。
  4. 重试中状态行：点击「重试」后错误行替换为「⟳ 正在重试…」，回合首个事件到达或再次失败即切换；复用 model-retry-notice 的行样式词汇。
  5. 失败计数与升级建议：同一会话尾部连续错误 ≥2 时追加琥珀行 + 内联「切换模型」链接（复用现有 openCustomModelSelector 入口）；重试成功或切换会话后清零。
  6. i18n 中英成对新增 key：生成失败前缀、重试中、升级建议、详情；errorContinueAction「继续生成」文案随按钮移除（errorContinueMessage 保留给潜在的继续场景）。
  7. 用户消息 hover 行的 ↻ 重试入口与 allowRetry / readOnly / side-chat 门控全部保留不动。

明确不做：详情只读查看原文，不加复制按钮、「从断点继续」入口；不动 SSE 重连提示与模型流自动重试（另两层，自动恢复语义）；不动「已停止」标签（aborted 是用户意图，刚定稿）；数据层 errorMessage 保持英文原文（去重与 trace 比较依赖）；不自动重试终态错误（会重复计费）；不新增依赖与色值（琥珀复用 #d97706，红只保留 destructive 文字/图标）。
