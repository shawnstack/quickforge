8 个具体问题 误触 / 认知负荷 / 流程黑盒
P1动作过载，且危险动作紧挨安全动作

一行里 4 个 16px icon-only 按钮（暂停 / 编辑 / 清除 / 详情）同权重相邻；「清除目标」和「查看详情」只差一个字形，而取消目标 不会回滚已改动的文件。

改：保留 1 个主操作 + 1 个「⋯」菜单，危险动作进菜单并二次确认。
P2没有进度感，只有轮次数字

条带只有 3/20，验收标准通过数完全不可见。用户无法回答「离完成还有多远」「还差哪几条」——而这正是 goal 模式唯一的价值主张。

改：加验收分段条 3/6 + 就地展开清单。
P3信息层级扁平

状态词、objective、轮次、错误全部 11–12px，只靠颜色区分。扫视时眼睛没有落点，长目标被 ellipsis 截成半句。

改：状态 → 目标 → 进度 三级字号/字重，目标允许 2 行。
P4同一个图标两种结果

预算耗尽时，暂停/继续按钮被路由成「打开详情」（goalBudgetExtension().exhausted 分支）。同位置、同图标、不同行为，用户不可预测。

改：预算耗尽用独立文案「追加预算并继续」，不换语义。
P5看任何细节都要跳面板

验收标准 / 证据 / 追加预算全部在右侧 GoalInspectorContent：条带 → 面板 → <details> → 按钮，3 层且丢失对话上下文。

改：条带就地展开前 5 条验收，面板保留为完整视图。
P613 个状态词，用户只需要 5 个

planning / awaiting_confirmation / verifying / pausing / needs_review… 被分别映射成 13 个中文词。用户真正关心的只有：在跑 / 要我做点什么 / 停了 / 卡了 / 完了。

改：5 个主状态词 + 1 个次要阶段标签。
P7取消确认把单行撑成两行

用 :has() + flex-wrap 在行内塞入说明文字和两个按钮，整条高度突变、居中的 fit-content 宽度重排，视觉跳一下。

改：危险操作用锚定 popover，不改变条带布局。
P8流程是黑盒，收尾是空白

「规划轮只读 → 计划保存后自动执行」只有一行小字；用户没预期它会自己跑起来。complete 之后条带 return null 直接消失，没有结果汇总，也没有「基于这个结果开新目标」的出口。

改：计划门禁卡（可选）+ 完成卡。

为什么能减到 5 个：「规划中 / 验证中 / 暂停中」是过程态，用户此刻不需要做决定，降级为次要标签即可；「等待审批 / 等待回答」本质都是「要你点一下」，合并为「需你处理」并把按钮变成滚动定位而不是打开新面板。

收益

  • 危险动作从 4 个并列降到 0 个显性（全进「⋯」），误触面消失
  • 「还剩几条验收」成为第一眼信息，goal 的价值被看见
  • 零跳转：看验收 / 看预算 / 追加预算全部就地完成
  • 改动集中在 GoalControlStrip.tsx + 一段 index.css，不动服务端契约

代价 / 风险

  • 条带从 32px 长到 ~76px，占 composer 上方空间（可用默认折叠缓解）
  • goal-control-strip.test.ts 的商品契约需同步（child order / aria）
  • 需要服务端暴露 criteria 汇总（goal.criteria 已有，纯前端可算）

  • 抽屉展开会遮挡消息，需要 position:sticky 与滚动容器的配合
  • 不再是 composer 的「输入附属物」，与 Todo 胶囊的视觉语汇需要重新对齐
