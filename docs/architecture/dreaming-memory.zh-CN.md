# Dreaming 记忆固化系统（已废弃）

> **这份文档描述的实现已经整体退役，不要按它写代码。**
>
> 现行设计见 [记忆体系：工作记忆 + 经验库](./memory-system.zh-CN.md)。

## 它以前是什么

Dreaming 曾经是一个「一次 LLM 调用改写一份 bullet 列表」的后台任务：

```txt
时间窗口内的会话（只取用户发言 + 助手最终答复）
        ↓
单次模型调用：当前笔记 + 新会话 → 新的完整笔记
        ↓
DREAMING.md 整份覆盖（与 MEMORY.md 是两个独立文件）
        ↓
两份文件一起注入系统提示 + recall_experience 工具按关键词过滤
```

## 为什么退役

四条各自独立的理由，任何一条都足以推翻它：

1. **一份列表装不下两种东西。** 「这个项目现在是什么样」和「遇到同类问题怎么做」的生命周期完全不同，混在一份列表里，要么短期细节把长期经验挤掉，要么反过来。
2. **整份覆盖意味着一次跑偏就全没了。** 模型返回一段散文而不是 bullet，代码只能拒绝整轮；返回了但质量差，就只能靠人发现。
3. **一次调用看所有会话。** 为了迁就单次调用的上下文预算，会话被截断、被合并，模型还得在脑子里做跨会话去重。
4. **`recall_experience` 是个多余的中间层。** 笔记本来就已经注入系统提示词了，再用一个工具去「检索」同一批文本，只是给模型多一条容易走错的路。

## 现在去哪找对应能力

| 以前的 | 现在 |
| --- | --- |
| `DREAMING.md` 的 bullet 列表 | `~/.quickforge/working-memory/`（活笔记）+ `~/.quickforge/experiences/`（经验库） |
| `recall_experience(query, kind)` | 索引常驻系统提示词，细节用 `read_memory_note` 直接读 |
| 单次调用看全部会话 | 一次一个会话，各起一轮 agent |
| 整份覆盖 + 行级 diff | 整目录快照 + 整轮回滚 |
| `pruneStaleNotes` 等剪枝设置 | 无。过期靠整理员改或归档，不靠按天数删除 |
