对照已落地的方案 A（.quickforge-goal-strip）逐项检查图标语义与视觉密度。每张问题卡里的条带都是按真实 CSS 复刻的当前渲染，可直接看出错在哪。

6 个具体问题
I1图标绑 tone，不绑状态

dangerouslySetInnerHTML: goalStatusIcon[view.tone]。5 个 tone ≠ 5 个状态：paused→info 借用了规划态的清单，waiting_*→active 和运行态共用时钟。

改：图标跟 data-state（5 词）走，或干脆固定为身份图标。
I2「已暂停」显示待办清单

规划态（planning / awaiting_confirmation）用的 checklist 被复用给 paused。用户看到「清单」会以为还有待办没做。

改：paused 用双竖线（pause）字形。
I3「需要你处理」是蓝色时钟

唯一需要用户动作的状态，配色却和执行态相同，既不抢眼也不可区分。设计稿里它是琥珀色。

改：tone 按 state 推导，needs_you → warning。
I4时钟还在旋转

.quickforge-goal-strip-icon--spinning 转的是时钟指针环，读起来像「加载中」，与「正在执行第 3 轮」不符。

改：旋转留给 running 的进度弧，静态状态一律不转。
I5点与图标重复编码

彩色图标 + 彩色点 + 彩色词三连，7px 间距内三个同色信号。点的呼吸动画本身已经足以表达「在动」。

改：图标中性灰，状态色只留「点 + 词」。
I6「已耗尽」chip 是蓝色的

.quickforge-goal-strip-chip 用 tone 12% 底 + tone 字。预算耗尽时 phase 仍是 active → 蓝色 chip，警示读不出来。

改：chip 固定 warning 语义色，不吃 tone。

已落地

要点：图标只回答「这是什么」（goal），文字只回答「现在怎样」（状态），颜色只回答「要不要管」（注意力）。三者各管一件事，不再互相代言。

「已完成」这一行只是把配色定下来——完成态目前仍不渲染条带（完成卡属设计稿方案 C）。

04

顺带修的样式微调

除图标外，还有 4 处尺寸/颜色问题，一并列出（都可独立开关）。

#现在建议理由
S1「已耗尽」chip 吃 tone（预算耗尽时是蓝色）固定 --destructive 或 warning 语义色警示不能跟运行态同色
S2身份行 7 个元素、gap .4375rem图标与词 gap 收到 .375rem；点与词之间 .3125rem；主操作前留 .5rem让「图标+点+词」读成一个整体，主操作独立成组
S3点直径 7px，与 16px 图标并排显得碎6px，呼吸环 3px→5px 不变与 3px 的验收分段条在同一粗细档位
S4min-width: min(100%, 20rem)，短目标也撑到 320px降到 18rem短目标时不再出现「大字在小框」的空旷感

不动：三段结构、⋯ 菜单、就地展开、锚定确认 popover、data-state 的 5 词映射、所有动作语义与共享锁。
