工具运行态反馈 · 8 个样式方案

统一前提：只作用于 running 态的工具标题（.quickforge-tool-label），done/error 不变，且都要有 prefers-reduced-motion 降级。下面每个方案都按「动的是什么 + 代价 + 是否符合 DESIGN_LANGUAGE」评估。 建议先把扫光定格看静态强度，再恢复动画看节奏。

A · 现状：currentColor 扫光
扫光取文字色 12%，浅色下是灰带，暗色下近白
基线
运行命令 · npm run build
代价：主题不自洽——同一份代码在浅色偏暗、暗色偏亮，看起来不像同一个设计。
符合规范：是（opacity/transform，无 filter / shadow）。
B · 分主题扫光（推荐）
浅色 foreground 10%，暗色纯白 20%
推荐
运行命令 · npm run build
代价：几乎为零，只多一个 CSS 变量 + 一条 html.dark 覆盖。
等于暗色下得到你要的“白色扫光”，浅色下仍是可见的柔光，不会失效。
C · 文字流光（渐变 text-clip）
渐变高光在文字内部流过，复用思考 shimmer 的范式
推荐
运行命令 · npm run build
效果：文字本身明暗流动，深浅色都天然成立，最接近“光扫过字”。
坑：必须只包住文字节点（detail 子元素会被 color: transparent 干掉）；emoji/图标不能进这个容器。
D · 呼吸透明度
整段标题 opacity 1 ↔ 0.5，1.8s
可选
运行命令 · npm run build
最省事、最稳（只有 opacity）。
坑：文字整体变淡会降低可读性，长耗时任务会觉得“字在喘”；无方向感，信息量最低。
E · 胶囊底色流光
给标题加淡底胶囊，扫光落在底色上
可选
运行命令 · npm run build
真实“扫光带”在浅色主题下唯一能看清的做法：靠底色承载光带。
坑：给纯文本加胶囊是新的视觉模式（DESIGN_LANGUAGE 里没有“行内状态胶囊”先例），且会抢占 chevron/状态的注意力。
F · 流动下划线
1.5px 光带在文字下方扫过
可选
运行命令 · npm run build
优点：不碰文字，可读性零影响；线条天然“克制”。
坑：容易和 hover 下划线、链接语义混淆；inset 改动会破坏现有 CSS 契约测试。
G · 字符波形
逐字错峰提亮，90ms 间隔
不推荐
运行命令 · npm run build
视觉上最“活”，但需要把标题拆成逐字 span。
硬伤：i18n 文本被拆散、无障碍朗读与选中复制受影响、DOM 数量随文案长度膨胀；DESIGN_LANGUAGE 明确不要逐项瀑布式动效。
H · 尾部呼吸点
文字恒定，仅在末尾加 4px 呼吸圆点
推荐
运行命令 · npm run build
优点：可读性最好、成本最低、深浅色都成立，和「按压回缩」同级克制。
缺点：信息量偏少（就是呼吸），但可用 aria-busy 承担语义。
怎么选
  • 想保留“扫光”这个语言 → 选 B（只改颜色取值 + 一条 html.dark 覆盖），是 A 的最小修复。
  • 想要更像“光”而不是“灰带” → 选 C，但需把「标题文字」和「参数 detail」拆成两个 span，改动面比 B 大。
  • 想彻底不折腾 → 选 H，把扫光换成呼吸点，代码最简单、可读性最好。
  • 不建议：D（文字变淡影响可读）、G（拆字伤 i18n 与复制）、E（引入无先例的行内胶囊）。
  • 若要组合，建议 B 或 C 二选一 + H 的静态语义，不要两种动效同时挂在一个标签上。
