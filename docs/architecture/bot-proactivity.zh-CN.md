# Bot 主动性:提示词驱动 + 最小 harness 补口

> 2026-11-12 立项。背景:用户反馈 bot 主动性不够——bot 应当能**主动干活**(自己发现并推进该做的事)、**主动汇报**(干完/出问题时主动通知用户)、**自我改进**(复盘自己的问题并改流程)。结论:以提示词驱动为主轴,harness 只补三个硬缺口(通知出口、催醒入口、投喂入口),一次落地;项目半径零代码复用 qf-api 既有通道(自发现 + spawn 子会话),自动盯盘与硬护栏为可选后续。

## 1. 现状边界

当前 bot 是「等投喂」的被动容器:

- **醒来的条件只有三类**(server/bots.mjs `inspectBotWork`,零 token 文件事实判断):从没醒过、自己目录里 `lastWakeAt` 之后出现新文件(含 `.bot/inbox.md`)、超过 3 小时强制兜底。感知半径 = 自己目录。
- **心跳指令抑制主动性**(server/bot-runner.mjs `heartbeatInstruction`):明示「不值得动就明说」「不要制造工作」。bot 有全套工具(读写自己目录、run_command、技能、qf-api 自省、给自己排定时任务),但指令气质是防守型。
- **干完没有出口**:心跳轮的产出只落进 bot 会话流;全局通知的两个触发源(用户开着的会话 `agent_end`、`scheduled_task_notification`)都不含 bot 心跳。唯一例外是 Android 端轮询 `/api/agents` 时因会话状态翻转发的通用通知。
- **入口是半成品**:`POST /api/bots/:id/wake` 与前端 `wakeBot()` 已存在但无 UI 调用点;`.bot/inbox.md` 只有判活读侧,没有任何写入者。
- **自我改进有素材没信号**:bot 有 MEMORY.md、经验库、qf-api 自省,但没有「上次哪里做得不好」的复盘动线。

结构性事实(本设计不改):bot 心跳与定时任务是两套互不相通的节拍;bot 给自己排的定时任务每次醒来是全新会话,仅靠 instruction 与 MEMORY.md 接续,这是 `<continuity>` 既定设计,予以保留。

## 2. 设计原则

1. **提示词优先**:能靠约定(指令文本、MEMORY.md 结构、消息标记)解决的,不加机制。
2. **harness 只补硬缺口**:出口(通知事件)、入口(催醒/投喂 UI)。判活逻辑、会话模型、通知通道、项目半径(qf-api 既有通道)全部复用现有设施,零架构改动。
3. **打扰要花钱**:[报告] 是稀缺资源,bot 每跳最多报告一次,无事不报告;通知只在有标记时发。
4. **不动**:多 bot 编排、会话存储、`inspectBotWork` 主逻辑、三条通知通道的实现(全局 SSE → toast/桌面、Android 轮询)。

## 3. 心跳指令与记忆模板重写(阶段 1,纯提示词)

改 `heartbeatInstruction`(server/bot-runner.mjs)与 bot MEMORY.md 默认模板(server/bots.mjs `defaultMemoryTemplate`)。设计取向:**极简、气质反转、回滚换自由**。

### 3.1 四条设计原则

- **极简且引导,不固定**:指令是「给有判断力的助手交代几句」,不是操作手册——不规定步骤、不规定记忆格式,给价值观(值得做的标准)、线索来源和边界。经三轮迭代(v1 六步固定动线 → v2 规矩清单 → v3 引导式)收敛。
- **记忆自我迭代**:MEMORY.md 的结构不是 schema,是种子。模板第一段明说「结构由我定,不好用就改」;bot 可以重组、拆分、换记法,唯一标准是「下次醒来的自己能快速接上」。
- **渐进披露**:MEMORY.md(每跳注入)始终一屏读完;细节拆成目录里的文件,记忆里只留去找它们的线索,醒来按需读。机制天然成立(注入的只有 MEMORY.md,其余文件本可读),无代码成本。
- **回滚换自由**:授权逻辑是「留痕再动手」——项目有 git 改动留工作区不 commit,没 git 先备份;做完记 `.bot/worklog.md`。有记录、可回滚,所以指令明说「大胆做,不用请示」。worklog 在 `.bot/` 下,判活扫描忽略该目录,记录增长不会误触发醒来。

三样东西钉死,因为它们是机制不是风格:**`[报告]` 首行**(服务端解析发通知)、**不 commit**(他人项目改动的撤销保障)、**目录边界**(沙箱)。

### 3.2 心跳指令(最终文案,v4)

```
[心跳] 你醒了,不是用户在说话。这是你的自主时间。

你的半径:自己的目录 {botPath} 随便写;别的项目,用 quickforge-api 能看见用户所有的会话与项目脉络,想深入就 spawn 一个绑定该项目的子会话去干——派活时把规矩带过去:改动留在工作区、不 commit、做完回报结果。

醒来先接上上次的自己:MEMORY.md 是你的记忆,不是别人的模板——结构不好用就重组它,装不下就拆成目录里的文件、只在一屏能读完的记忆里留线索。怎么记你说了算,标准只有一个:下次醒来的你能快速接上。

然后去做一件值得做的事。什么是值得,你自己判断——线索在记忆里、投喂里、会话与项目的变化里(git、测试、坏味道);改动小、见效快、失败了只亏一跳的先做。做了就做透,确实没有就探索出候选,或明说这一跳不动手、为什么。

动手前留痕,做完记录:改自己目录先备份;动别的项目走子会话并让它留痕。能回滚的事,大胆做,不用请示。要用户拍板的,写进记忆等他。

首行以 [报告] 开头,他才会收到通知(60 字内说清);没有就不带。不向他提问。
```

`{botPath}` 由 `heartbeatInstruction(bot)` 注入(与现有机制同款);不再注入 `{watchList}`——bot 的项目半径不靠配置,靠 qf-api 自发现(见 4.4)。相对旧版的关键变化:删「不值得动就明说」「不要制造工作」等防守指令;探索成为默认动作;记忆格式放开为自我迭代;半径如实描述(自己目录直接写、全局经 API 只读、他项目经 spawn 子会话);「不 commit」由主 bot 写进派活 prompt 传递给子会话。

### 3.3 MEMORY.md 模板(最终文案,v2 种子式)

```
# {bot 名}

常驻 bot。目录:`{路径}`。这份记忆是我的,结构由我定,下面只是起点,不好用就改。

## 在做的事
(下一件事从这挑:是什么 / 为什么值得 / 卡在哪)

## 等用户
(要他拍板的事,一条一件)

## 踩过的坑
(怎么踩的 / 下次怎么绕)

---
这份文件保持一屏读完;细节放目录里的文件,这里只留去找它们的线索。
```

相对旧版:删「我在意的事」里的「不确定的时候先问,不要自己造需求」(与主动探索冲突);「想做清单/等你/教训」改名「在做的事/等用户/踩过的坑」并降级为种子而非 schema;渐进披露写进模板尾部,作为 bot 对自己的约定。

### 3.4 报告契约(主动汇报的提示词侧)

- 心跳轮的回复**首行以 `[报告]` 开头**才视为有事要报告;首行其余文字作为通知摘要,控制在 60 字内、给出门径(什么干完了/什么出问题了/什么在等你决定)。
- 无事、纯清单维护、例行探索 → 首行不带标记,正常收跳。
- 什么值得报告:任务完成且结果影响用户、出错需要用户知晓、「等你」新增需要决策的事项。同一事项只报告一次。
- 该标记是服务端发通知的唯一依据(见 4.1),属于内部契约,不进用户文档。

### 3.5 自我改进

信号源不新增机制:自己会话上一跳的实际结果、worklog 里失败/半途的记录、投喂与「等用户」里用户的答复。复盘落点也由 bot 自己决定——种子模板给了「踩过的坑」节,但记什么、怎么记、要不要换成别的形式,都属于记忆自我迭代的范围。引导只保证两件事:踩坑有地方记(或 bot 自己建一个地方),以及「做透一件」的判断里天然包含对上次失败的复盘。连踩同一个坑两次要不要升级成「在做的事」,由 bot 自判,无代码强制。

## 4. harness 补口(阶段 2,小代码)

### 4.1 通知出口

- `runBotHeartbeat` 正常结束后,取该轮 assistant 回复首行:带 `[报告]` 标记 → 向全局事件通道 emit `bot_heartbeat_notification`(payload:botId、bot 名、会话 id、摘要文本),复用 `scheduled_task_notification` 的扇出模式(server/routes/scheduled-tasks.mjs 已有同款)。
- 前端:App 层全局 SSE 客户端新增对该事件的监听,走现有 `showTaskSystemNotification`(toast + 桌面通知),点击跳转 bot 会话。
- 无标记、idle 跳、报错跳(心跳自身失败)不 emit;报错跳仅沿用现有 lastError 记录,不弹通知(避免错误风暴)。
- Android 端不改:现状已可因会话状态翻转收到通用通知。

### 4.2 催醒入口

侧栏 bot 行(展开态)加「催一下」动作:调已有 `wakeBot()`;bot 会话 running 时禁用。不带确认弹窗(只读副作用:提前跑一跳)。

### 4.3 投喂入口

- 新增 `POST /api/bots/:id/inbox`(server/routes/bots.mjs):把文本追加写入 `.bot/inbox.md`(带时间戳分段),成功后把 `nextRunAt` 提前到当前时间(下一轮 runner 扫描即醒,无需直接唤醒,保持单飞约束)。
- 前端:bot 会话输入框旁加「投喂」模式(或 bot 面板投喂框,取实现更顺的一种):文本提交即入 inbox,不进会话消息流。
- qf-api 不新增投喂（inbox）子命令;投喂是用户动作,用户有 UI 就够。（2026-11-12 追注:qf-api 此后独立立项加了 bots 只读/创建/催醒子命令——见 `docs/architecture/quickforge-api-skill.zh-CN.md`——仍不含投喂与删改。）

### 4.4 项目半径:零代码,复用 qf-api 既有通道(原「多根沙箱」方案废弃)

用户核心诉求:bot 醒来要能看**用户的项目**——自由探索、审核、修 bug。曾设计 `watchProjectIds` + workspace 多根沙箱(extraRoots),后经核实**不需要动 harness**:bot 会话挂 quickforge-api 技能,既有白名单通道已覆盖全部半径,且均在 QuickForge 自己的权限模型内:

- **看见全局**:`sessions`(会话元数据索引)能读到用户所有会话及其项目脉络——bot 不需要「关注项目」配置就能自己发现用户在忙什么;`instructions?projectId=` 可按项目深入。
- **深入项目干活**:`spawn` 可派生**绑定任意注册项目的子会话**——子会话的 workspaceRoot 就是目标项目,读、审核、修 bug 都在那个项目的沙箱内完成,权限继承自 bot(full-access)。主 bot 通过派活 prompt 传递任务与规矩(不 commit、留痕、回报结果),通过 `show`/`messages` 取回结果。
- **本地事实**:run_command 可跑 git/npm 等(bot full-access 定位,既有行为,不因本设计改变)。

半径三层的分工:自己目录**直接写**;全局**经 API 只读**;他项目**经子会话写**(沙箱 = 该项目)。多根沙箱方案废弃原因:动的是全工具共享路径校验(server/utils/workspace.mjs),成本与风险高,而 spawn 通道零代码达到同等效果。`watchProjectIds`/`extraRoots` 降级为阶段 3 可选(spawn 路径实测体验不佳时再评估)。

副作用顺带成立:bot spawn 的子会话出现在用户的会话列表里(带标题),用户可见、可中止——bot 在他项目的动作天然可观察。

## 5. 感知半径(修订 v2)

bot 对外界的感知零代码承载:醒来后经 qf-api 看全局脉络,经子会话或 run_command 深入项目(git 状态、最近提交、失败测试、坏味道),审核与修 bug 都在授权内。醒的节拍 = 投喂 + 催醒 + 3 小时兜底;不自动盯盘(不因项目变化自动唤醒)。

可选阶段 3(单独立项,不在本次范围):判活半径扩展(项目变化唤醒 bot)、`watchProjectIds`/多根沙箱(spawn 路径体验不佳时的替代)。

## 6. 护栏与风险

- **单跳纪律(提示词层)**:一跳只推进一件主要事项;超出的写记忆。
- **写他人项目的风险**:经 spawn 子会话发生,最坏情况 = 用户项目工作区里留下不想要的改动。缓解:①「不 commit」由主 bot 写进派活 prompt(提示词约束,非服务端强制——如实记录此弱点);②改动永远留在工作区,`git checkout` 即可全部撤销;③子会话在会话列表可见可中止;④worklog 留痕。
- **已知风险**:心跳轮无运行超时与 token 预算(与定时任务的执行超时机制不对称)。指令更主动后,单跳变长的概率上升;阶段 3 可选补单跳超时 + abort,以及「每 bot 每小时通知上限」。失控的首要可观察信号:侧栏状态小字长时间「在忙」、wakeCount 激增。
- **通知噪音**:[报告] 契约 + 同一事项只报一次,由提示词约束;若实测仍吵,阶段 3 再加频率上限(代码)。

## 7. 落地与验证

一次 feature 内完成阶段 1 + 阶段 2(阶段 2b 已废弃,harness 不再有任何共享路径校验改动):

| 阶段 | 改动 | 验证 |
|------|------|------|
| 1 | `heartbeatInstruction` 重写(§3.2 v4 文案)、`defaultMemoryTemplate` 重写(§3.3 v2 文案,含 worklog/留痕约定) | 更新 `tests/server/bots.test.mjs` 中指令与模板相关断言;`tests/server/routes/bots.test.mjs` 不应回归 |
| 2 | `[报告]` 标记解析 + `bot_heartbeat_notification` 事件;前端全局 SSE 监听 + 通知;催醒按钮;`POST /api/bots/:id/inbox` + 投喂 UI | 新增/更新 `tests/server/bots.test.mjs`(标记解析)、`tests/frontend/bot-heartbeat-message.test.ts`(标记识别)、routes 测试(inbox 端点);`npx eslint` 0 problems;`npm run build` 通过 |

阶段 2 收尾跑全量 `npm run test`。阶段 3 可选项(判活半径扩展、watchProjectIds/多根沙箱、单跳超时、通知上限、Android 文案 bot 化)记入 Notes,按需立项。

## 8. 边界(明确不做)

- 不做多 bot 编排与多 bot 间通信。
- 不改 `inspectBotWork` 判活语义、不改 workspace 单根沙箱(本次零 harness 架构改动;多根属阶段 3 可选)。
- 不新增独立推送通道,不因 bot 改造桌面/Android 通知实现。
- qf-api 不加 bots 子命令、不动白名单;bot 会话与定时任务的双节拍结构保持现状。
- 不做「不 commit」的服务端强制(提示词约束 + git 兜底);不做读写分级与文件类型白名单。
