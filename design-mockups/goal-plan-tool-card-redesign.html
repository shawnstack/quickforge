问题分析 · 计划工具调用与对话正文的字体不一致

goal 期间的计划工具调用（goal_report / todo_write 卡片）渲染在对话流内（light DOM，可直接受全局样式影响），但字号走的是「界面字号」rem 体系，而对话正文走「消息字号」token 体系；默认 13/13 时两者恰好相同，一旦在设置中分开调整立即分叉。以下每条均附源码证据。

P01字号双轨制：卡片正文跟随界面字号，对话正文跟随消息字号

卡片正文（目标摘要、验收项、blocker、输出）无任何显式字号规则，继承 rem 基准＝界面字号；对话正文走 --quickforge-message-font-size，由设置页独立写入。两轨一旦分叉，同一条消息流内出现两种正文字号。

src/index.css:117-119 html { font-size: 13px }（界面字号 rem 基准） src/index.css:7030-7032 .quickforge-goal-report-tool-body { padding… }（仅内边距，无字号） src/index.css:2628-2632 markdown-block { font-size: var(--quickforge-message-font-size, 14px) } src/lib/font-size-settings.ts:11-19,79-99 两个设置项（默认均 13px）分别写入 root.style.fontSize 与 --quickforge-message-font-size

提案 S01/S04：工具卡正文显式改用 var(--quickforge-message-font-size)。

P02卡片内部层级混乱：0.875rem / 0.75rem / 1rem 多套并存

同一张卡片内：摘要行 0.875rem、节标签 0.75rem（text-xs）、正文 1rem，全部锚定界面字号；goal 运行条、todo 胶囊又各自使用 0.75rem/650、0.8125rem、0.6875rem。没有一套以「对话正文」为基准，视觉轴不齐。

src/index.css:3056-3064 .quickforge-local-tool > .quickforge-tool-summary { font-size: 0.875rem; font-weight: 400; line-height: 1.5 } src/lib/local-tools.ts:1099-1105 节标签使用 Tailwind text-xs（＝0.75rem） src/index.css:6888-6893 goal strip label 0.75rem / weight 650 src/index.css:7685-7697, 7746-7750 todo 胶囊 0.8125rem 与 0.6875rem

提案 S02：层级保留（弱化比例不变），基准统一换成消息字号：正文 ×1、摘要行 ×0.875、节标签 ×0.8。

P03行高差异：正文 1.625 vs 卡片 1.5（未显式声明）

对话正文 p/li 显式 1.625；工具卡摘要行 1.5，卡片正文则完全未设置行高（继承预检 1.5）。中英混排多行验收项与同一屏的正文行距观感不一致。

src/index.css:2634-2637 markdown-block :where(p, li) { line-height: var(--quickforge-message-line-height, 1.625) } src/index.css:3063 tool summary line-height: 1.5；tool-body 无行高规则（src/index.css:7030-7032）

提案 S03：卡片正文/验收项/blocker 行高对齐 1.625；摘要行保持 1.5（单行操作行，紧凑可接受）。

P04同类问题已有先例修复，goal 卡片被遗漏

Subagent 运行详情正文曾因同一原因（不经 quickforge-* 装饰、字号掉回界面字号）被显式补齐，注释写明「避免与主对话字号不一致」；goal_report / todo_write 卡片没有对应规则，属同一缺口。

src/index.css:2639-2648 subagent-run-detail-body markdown-block { font-size: var(--quickforge-message-font-size, 14px) }（含注释）

提案 S04：为计划工具卡补同模式规则，落点见页脚对照表。

P05局部异质元素：scope chip 游离于两套体系之外

范围 chip 使用 mono 字体（路径语义，可保留）但字号 0.7rem 独立锚定界面字号，是卡片内唯一显式指定 font-family 的文本；font-family 主链路（--font-sans，含 PingFang SC / Microsoft YaHei / Noto Sans CJK SC 回退）本身一致，问题集中在字号基准。

src/index.css:7075-7083 .quickforge-goal-report-scope-chip { font-family: var(--font-mono); font-size: 0.7rem } src/index.css:49-55 --font-sans / --font-mono 字体栈定义

提案 S05：chip 保留 mono 语义，字号并入节标签层级（消息字号 ×0.8）。
