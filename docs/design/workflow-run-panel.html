02 · 为什么是这三个视图

不是把聊天里的卡片放大，而是各答一个只有右侧面板才答得了的问题。

时间轴 回答「串行还是并行」

数据里已经有 seq + startedAt + durationMs，画出来就是真实甘特图。

并行段在聊天卡片里永远看不见（那里只能一行一行列），只有拉平成时间轴才显形。

阶段 回答「跑到哪了」

脚本用 phase() 声明的意图结构，是人和模型共享的心智模型。

Agent 卡 + 工具行沿用现有渲染逻辑，只换容器，迁移成本最低。

日志 回答「为什么卡住」

服务端环形保留 200 条，带 phase 与 error 级别。默认全显，不折叠。

带相对时间戳（0.00s / 3.20s），比绝对时间更易读。

03 · 布局与交互规格

项规格依据
面板宽度 默认 560px（打开 workflow Tab 时自动从 380 拉宽） 现有 AUTO_EXPAND_WIDTH = 640 阈值，560 是甘特图可读下限
Tab 标题 「工作流 · 5 阶段」，按 runId 去重 同 upsertSubagentRunTab，重复点击只聚焦
视图切换 分段按钮，记住上次选择（localStorage） 无对应现有模式，新增一个轻量 useState + 持久化
时间轴左侧标签 固定 200px 文字列，超出省略 与右侧时间轴分离，避免条形挤压
条形高度 Agent 10px / 工具 6px 高度即层级，不再靠字号逐级缩小
最小可见宽度 3px（极短工具调用） 避免 0.05s 的调用消失
并行标记 虚线描边 + 「并行」文字 颜色之外的第二编码，色盲可用
底部固定区 脚本 / 结果 / 复制轨迹 结果与脚本体量大，不占主滚动区
