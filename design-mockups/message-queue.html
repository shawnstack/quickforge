方案概览

普通排队：流式期间按 Enter 不再被丢弃，消息进入本地队列；回合结束（agent_end）后自动逐条 prompt()，表现为用户消息依次出现在对话里、各自触发正常回合。

立即插队：点击队列项上的「↑ 立即」，调用已有的 ServerAgent.steer() —— pi-agent-core 会在当前工具轮/思考/回答结束后、下一轮开始前注入这条用户消息，剩余排队项保持原顺序继续等待自动发送。

拖拽排序（新增）：手柄触发（与按钮/文本选择零冲突）；按下后超过 6px 阈值才激活；原位半透明占位 + 克隆幽灵跟随，越过相邻行中线即换位实时预示落点；松手提交顺序、刷新序号并照常持久化。实现走 ~80 行指针事件 mini-sortable（支持触屏），不引入 React 版 @dnd-kit 依赖。

时序示意

  • 运行中 → 排队 [B, C]，当前正在跑工具轮 N
  • 点 C「立即」→ 工具轮 N 结束 → C 注入对话（steer）→ 继续响应 C
  • 整回合结束 → B 自动作为新回合发送
  • 不点立即 → 整回合结束后 A→B→C 按提交顺序各自成为新回合

关键事实（调研结论）

  • 后端能力已存在：server/agent-manager.mjs steerAgent/followUpAgent 与路由 POST …/steer | /follow-up，前端 src/lib/server-agent.ts 已有 steer()/followUp() 方法，但全 UI 无调用点。
  • 现状：流式期间第二次发送在 AgentInterface.sendMessage 被静默丢弃，服务端第二个 prompt 返回 409 GENERATION_ALREADY_RUNNING。
  • 「停止」是显式 API（POST …/abort），本方案的插队不使用 abort，不打断正在执行的工具。
  • 队列 UI 可复用 todo-write-summary 的挂载位（composer shell 内、message-editor 前），草稿持久化可复用 composer-drafts localStorage 通道。

待你确认的问题

  1. 插队实现路线：推荐 steer()（真·轮边界注入，后端现成）；备选是"立即=abort 当前回合+马上发"，更简单但会砍掉进行中的工具。
    演示稿按 steer 语义做的。
  2. 手动停止后队列怎么办：推荐暂停并给「继续」按钮（手动停止通常意味着想改方向）；也可以选择继续自动发。
  3. 出错的回合后是否继续队列：推荐暂停 + 重试/清空入口。
  4. OpenCode 会话：推荐只提供普通排队（回合结束后逐条发），隐藏「立即」按钮；或整个功能在该 harness 下禁用。
  5. 插队的可见性：插入成功后在对话流里显示一条细的边界标记（如本演示的「⚡ 已在轮边界插入」），还是完全不加标记？
